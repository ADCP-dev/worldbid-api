# Email Development Documentation

This document provides information about the email system in Foundation NestJS, how to develop and test emails, and the underlying architecture.

## Mail Module Structure

The mail module is located at `src/modules/communications/mail` and has the following structure:

```
src/modules/communications/mail/
├── config/                  # Mail configuration
├── interfaces/              # Mail interfaces
├── mail-templates/          # Email templates
│   ├── build/               # Built templates (generated by Maizzle)
│   ├── emails/              # Email template "pages"
│   └── layouts/             # Email layouts
├── mail.module.ts           # Mail module definition
└── mail.service.ts          # Mail service implementation
```

## Email Templates

The application uses [Maizzle](https://maizzle.com/) as the email template development framework and [Handlebars](https://handlebarsjs.com/) for template rendering with [Nodemailer](https://nodemailer.com/about/).

### Directory Structure

- **build**: Contains the compiled and optimized email templates produced by Maizzle
- **emails**: Contains the email template "pages" that you develop (source files)
- **layouts**: Contains layout templates that wrap around your email content

### Assets

Static assets for emails (images, etc.) are served from the `/public` directory of the application. When referencing assets in your email templates, use absolute URLs.

## Development Workflow

### Developing Email Templates with Maizzle

Maizzle provides a powerful framework for building responsive HTML emails. To work with email templates:

1. **Start the development server**:

   ```bash
   npm run maizzle:serve
   ```

   This will start a development server on port 3001 where you can preview your email templates as you develop them.

   > **Note**: If you encounter errors, make sure your layout files have the `.html` extension.

2. **Build email templates**:

   ```bash
   npm run maizzle:build
   ```

   This command compiles, optimizes, and generates the final email templates in the `build` directory.

### Email Testing with Mailpit

For local development and testing of emails, the application uses [Mailpit](https://github.com/axllent/mailpit), a local SMTP testing tool:

1. **Start Mailpit**:

   ```bash
   docker compose up -d mailpit
   ```

2. **Access the Mailpit UI**:

   Open your browser and navigate to [http://localhost:8025](http://localhost:8025)

3. **Testing emails**:

   When your application sends an email during development, it will be captured by Mailpit and displayed in the UI. This allows you to see exactly how your emails will look without actually sending them.

## Using the Mail Service

The `MailService` (src/modules/communications/mail/mail.service.ts) handles the sending of emails in the application. It uses the following key components:

1. **Handlebars templates**: For rendering dynamic email content
2. **Nodemailer**: For sending emails
3. **i18n**: For internationalization of email content

### Current Email Types

The mail service currently supports several types of emails:

1. **User Sign Up**: Confirms user registration
2. **Forgot Password**: Sends password reset links
3. **Confirm New Email**: For email address changes

### Adding a New Email Template

To create a new email template:

1. Create a new template file in `src/modules/communications/mail/mail-templates/emails/`
2. Use an existing layout or create a new one in `src/modules/communications/mail/mail-templates/layouts/`
3. Build the template using `npm run maizzle:build`
4. Add a new method in the `MailService` to send the email

### Example

```typescript
async newEmailType(mailData: MailData<{ customData: string }>): Promise<void> {
  const i18n = I18nContext.current();
  // Get translations
  let emailTitle: MaybeType<string>;

  if (i18n) {
    emailTitle = await i18n.t('common.emailTitle');
  }

  // Send email
  await this.mailerService.sendMail({
    to: mailData.to,
    subject: emailTitle,
    templatePath: path.join(
      this.configService.getOrThrow('app.workingDirectory', {
        infer: true,
      }),
      'src',
      'modules',
      'communications',
      'mail',
      'mail-templates',
      'build',
      'your-template-name.hbs',
    ),
    context: {
      // Template variables
      title: emailTitle,
      customData: mailData.data.customData,
    },
  });
}
```

## Best Practices

1. **Test all emails** in multiple email clients using Mailpit during development
2. **Use responsive designs** that work on both mobile and desktop
3. **Minimize the use of images** and complex CSS that might not be supported by all email clients
4. **Always provide plain text alternatives** for accessibility
5. **Keep templates in the correct directories** to maintain organization
6. **Use i18n for all text** to ensure proper internationalization
